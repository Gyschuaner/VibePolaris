# BUG-7D1E86C9 · 搜索工具动画方向探索

本次修改服务于 2026-10-17 DeepSeek 新闻里“编程助手怎样用上新开放的网页工具？”这一读者问题。用户提供了实际页面截图，明确认为编号圆点、椭圆虚线、STEP 说明和底部步骤按钮像卡片式 PPT，要求别出心裁地重新设计。目标读者是尚不了解工具调用、搜索与抓取差别的普通读者。演示必须让对象的变化承担解释任务：先看到可供选择的网页线索，再看到选定网页的正文被取出，最后看到正文进入模型使用的工作区。读者即使暂时不读正文，也能沿着同一个内容对象理解因果关系。

保留网站现有的纸面、苔绿和墨色语境：背景 #F7F3E8，纸张 #FCFAF3，正文 #171A15，次要文字 #686E64，分隔线 #DAD8CD，强调 #52683F。展示字可用本机宋体，内容用本机苹方，接口名用等宽字；不引入在线字体和新依赖。每个方向统一为自包含 HTML，基准画布 1000×560，外围可有简短标题、交互入口与真实的暂停、重播控制。画面文字尽量少，只保留本次动作必需的角色、输入、动作和结果，不叠加重复解释、状态脚注、无意义数字或计时器。

三版的结构和运动逻辑必须不同，而非同一布局换肤。每版从自己的意象和运动规律出发，不参考其他方向。纸张可以是信息对象，但禁止用几块等大的讲解卡片排列步骤、禁止 1/2/3/4 编号与步骤导航、禁止只淡入淡出说明文字。避免粒子、发光、抽象轨道和无意义的 UI 装饰。三个方向各自需要一个值得暂停观察的定格帧。主角必须明确，画面在关键位置留出未完成的内容，再用对象动作兑现结果。交互有实际可见反馈，不做装饰性的按钮。

事实边界：模型提出工具请求，由运行框架执行并把结果交回；Search 根据 query 返回结构化搜索结果，允许按需带正文；Fetch 根据某个 URL 返回 Markdown 正文。本样例演示需要进一步读取其中一页的情况，不能写成每次 Search 都必须 Fetch，也不能画成模型直接联网。使用“框架执行 Search / Fetch”等必要标签承载边界即可，不需要技术注脚。样例内容明确为机制示意，无真实网络调用，不编造产品界面或测量结果。计费解释留在文章正文，本次动画只聚焦资料如何进入工作区。

本阶段交付三个可运行方向和截图，用户选择前不改新闻渲染器，不改变其他文章的 agent-workflow。用户选择后才实现对应生产组件，覆盖暂停、重播、键盘及减少动态偏好，并进行构建和本篇浏览器验收。
