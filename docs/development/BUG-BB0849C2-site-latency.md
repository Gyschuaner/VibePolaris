## 定位与实现

- BUG-BB0849C2（VBP-047）：全局小北静态引入完整 Markdown 排版；改为打开对话时加载 Transcript，将轻量上下文容量控件独立。稳定关闭回调并 memo 旧消息，避免新字输出带动全部旧回答重新排版。
- 同一 Bug：意图分类原先也启用 high 思考，但等待全部分类完成后才开始答疑；分类改为不思考、最多 256 个输出 token 的短 JSON。正式回答保留原有 thinking/high；鉴权、计费、取消、分类拒绝和异常处理沿用现有路径。
- BUG-D35AC097（VBP-012）：专属词条由同一服务端路由静态引入，生产公共脚本达 8,600,665 字节（gzip 2,661,655 字节）。在客户端增加 Next dynamic 边界，仅加载实际渲染的页面。332 个路由映射及 SSR 正文保留，原有分组模块仍按组复用。

采用客户端边界是因为服务端直接动态引入客户端组件目前不能自动拆分客户端脚本，见 [Next 官方说明](https://nextjs.org/docs/app/guides/lazy-loading)。没有禁用 SSR。
