# VBP-101 可选账号、私有画布同步与小北授权

## 用户行为

用户名密码登录为可选项。游客继续使用原浏览器画布；登录不会上传该画布。用户选择「开启云端同步」后，确认名称及是否自动同步，将节点、Markdown、位置、连线完整保存到账号，游客原件保留。两个浏览器的独立内容保存成不同画布，不按标题猜测去重；相同迁移来源及本地版本的请求重试返回同一张云画布。

「自动同步到云端」由用户开启，偏好按账号、浏览器保存。关闭后仍自动写入本地，可手动同步；已有云内容保留。再次开启先核对云端版本。账号画布和笔记深链接带 `canvas` ID；无权访问时返回404，仍能切回此浏览器的画布。原有文章批注、划线和随手记继续本地保存，本次未将它们迁移到云端。

邀请码绑定一次后覆盖账号所有现有和新登录会话，聊天及画布补全沿用同一邀请码账本。绑定只迁移已证明归属的当前浏览器对话，不能凭同一邀请码读取其他游客的历史；旧浏览器登录绑定账号后可主动保存自己的旧对话。已存在的游客小北会话保留原到期时间与同一账本，避免丢失旧历史；已绑定的邀请码不再建立新的游客激活。补全扣费开关保持 `false`，聊天计费不变。

## 数据和权限

复用 `XIAOBEI_DB_PATH` 指向的 SQLite 与持久卷，按需新增 `accounts`、`account_sessions`、`account_invites`、`account_attempts`、`account_canvases`。旧邀请码、积分、聊天表及游客 IndexedDB `main` 不重建。用户名经NFKC、去空格、小写规范化；密码15–128位，独立随机盐加原生scrypt（N32768/r8/p3），散列并发最多2个。会话随机32字节，服务端只存散列，HttpOnly、SameSite Strict，HTTPS时使用Secure；凭据接口同源检查、限流。

云端操作同时检查登录会话和数据所属账号；私有接口 `no-store`。写入与小北请求携带创建请求时的 `X-VP-Account`，避免旧账号队列在下一账号的Cookie下执行。本地云数据按 `account:<owner>:<canvas>` 分区，退出前先保存本地草稿；切换账号重新挂载画布和小北，关闭旧流及临时界面状态。

当前每账号最多20张画布、合计100MiB，每张25MiB、2000节点、6000连线。超额拒绝上传，本地草稿保留。第一版未提供账号找回、云画布删除或重命名管理；注册时说明当前不支持邮箱找回。SQLite及其备份须按私有用户数据管理。

## 同步与冲突

本地先持久化，自动同步防抖1秒，可见时8秒条件轮询，恢复联网或聚焦时刷新。ETag避免未变化时重传完整画布。服务端以版本CAS拒绝旧版本覆盖。客户端保留上次确认的基线，三方合并独立节点和不同字段的编辑，位置作为一组，视口仅设备本地。节点删除与另一端编辑相遇、或同字段不同修改时，将本地完整画布另存为冲突副本，原画布保留云端版本。

生成副本后，在一个IndexedDB事务中写入副本草稿并将原缓存推进到云端基线，避免返回原画布时重复派生副本。初始化加读取锁，避免StrictMode或聚焦触发的并行读取互相误报本地版本冲突。对应修复为 `BUG-86AA3DED`。多窗口本地CAS失败时继续保留当前内存草稿，提供导出及重新载入，拒绝静默覆盖。

## 部署与回退

无新依赖和配置必填项。需沿用有持久卷的服务部署方式，部署前对当前SQLite执行在线备份和完整性检查。所有表均为增量新增，回退旧镜像时保留当前数据库及持久卷，不能用发布前旧库覆盖新增用户内容；旧程序暂不提供账号入口，但游客原件及旧小北账本仍可继续使用。再次部署新镜像即可恢复账号云数据。客户端仍为原IndexedDB数据库版本，旧程序只使用原 `main` 键。
