# VBP-077 机制差异矩阵

这张矩阵先固定十条词条各自要让零基础读者看见的变化，再决定正文顺序和演示形状。每条页面都保留自己的场景、失败分支和停止条件。

| slug | 读者遇到的任务 | 核心变化 | 专属演示 | 边界/失败 |
| --- | --- | --- | --- | --- |
| `transformer` | 为什么同一段文字里前后词会互相影响 | 多层注意力与前馈变换把 token 表示逐层改写 | 一句话的 token 卡片经过层叠轨道，关系线让“银行”在不同上下文中变色 | 层数增加不等于事实正确；表示变了不等于查过资料 |
| `attention` | 模型这一刻在看输入的哪几处 | query 与 key 计算权重，再汇总 value；权重随输入和 mask 变化 | 点击“返程时间”或“地址”，同一行 token 的聚光范围变化 | 高权重不是解释，也不是模型一定正确地理解了这段话 |
| `inference` | 模型已经训练好后，一次回答到底发生什么 | 固定权重接收输入，经历 prefill，再逐 token 解码 | 请求进入、首 token、后续 token、停止条件与延迟条依次出现 | 推理不会更新训练权重；超时、截断和采样都会改变结果 |
| `pretraining` | 模型为什么会有通用语言能力 | 大量 token 经过目标构造、预测、损失和权重更新 | 文本流切片，遮住下一个 token，误差回传后权重刻度微调 | 训练数据偏差会进入能力；一次训练样本不是事实核验 |
| `kv-cache` | 长回答为什么后半段不用重算整段前缀 | 已处理前缀的 key/value 保留，后续 token 复用 | 第一 token 全量计算，后续 token 显示 cache hit；改前缀后整段失效 | cache 只复用计算，不扩大窗口；前缀变化、超时会失效 |
| `agent-workflow` | 固定步骤和智能体自己选下一步有什么区别 | 程序预先规定节点/条件，模型只在被允许的节点参与 | 发布流程的检查、审批、部署闸门按固定路径亮起；缺检查则停 | workflow 不是自动正确；开放选择应另看 agent loop 与权限 |
| `backpressure` | 生产者太快时，系统怎样不被压垮 | 消费速度不足把压力沿队列反馈，触发等待、限流或丢弃策略 | 订单传送带水位升高，消费者变慢后生产入口暂停/拒绝 | 无限排队会耗尽内存；丢弃策略必须可见且可恢复 |
| `dead-letter-queue` | 一直失败的消息最后去哪 | 重试耗尽或不可处理消息转入隔离队列，保留失败原因 | 消息经过重试计数，进入 DLQ，再修复后人工/程序重放 | 进 DLQ 不是成功；重复重放仍可能有副作用 |
| `eventual-consistency` | 为什么刚写入的数据另一处暂时看不到 | 多副本异步传播，读取在一段时间后收敛到同一值 | 主副本写入，副本显示旧值，传播完成后版本一致 | 收敛时间无保证时不能马上依赖读结果；冲突需要规则 |
| `feature-flag` | 新功能怎样只给一部分用户，出问题能关掉 | 运行时条件把代码路径切换到不同实现 | 同一请求按用户/环境命中旧、新路径，关闭开关立即回退 | flag 不是权限系统；长期 flag 会形成组合和清理负担 |
