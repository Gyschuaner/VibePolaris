正式内容同步至[现有方案文档的 R4 章节](https://ycn7t34xe864.feishu.cn/docx/VWilddQlHoNCEqxlGNjcEwMnn5f)。文档原有标题和图片保留作历史参考。本 R4 取代 R3 的“17 秒自动播放为主”和“检查失败作为主线”建议。下述分组与教学编排是本项目设计判断，并非行业统一组件标准。

## 概念边界

Agent Harness 是模型外围、让它持续完成任务的运行系统：准备模型输入，调用模型，接住工具请求，安排执行，把结果送回后续模型调用，并管理运行约束与状态。

模型负责理解与选择下一步；工具真正读取文件、修改内容或调用服务；Harness 负责把这些过程组织起来。工具执行环境可以在独立沙箱、用户电脑或远端服务中。不能把模型、Harness、工具、沙箱画成一个不可分辨的大脑。

“狭义运行时”和“广义 Harness Engineering”需要区分。Anthropic Managed Agents 将会话、Harness、沙箱分开，Harness 主要承担模型调用与路由；Claude Code 文档用更宽的产品视角描述工具、上下文和执行环境；OpenAI 的 Harness Engineering 还讨论项目知识、架构规则、测试与反馈环境。词条首讲运行机制，工程实践放在后续展开。[S1][S2][S3]

## 应该讲哪些部分

以下按六组职责组织教学。前三组构成一个使用工具的最小运行循环；后三组帮助它在真实任务中受控、持续并可检查。能力可能由 Harness 自己实现，也可能通过外部基础设施接入。

| 部分 | 实际职责 | 初学者要看见的证据 | 教学位置 |
| --- | --- | --- | --- |
| 上下文与指令 | 组织任务、规则、可用工具说明、对话和工具结果；按容量选择或压缩输入 | 第一次调用只有任务与工具说明，读取后的第二次调用新增文件内容 | 主线 |
| 模型调用与循环控制 | 发起模型调用，处理回答或工具请求；依据结果及运行策略继续、结束或暂停 | 第一次调用发出读文件请求；工具返回后发生第二次调用 | 主线 |
| 工具接口与执行调度 | 定义工具及参数，检查请求结构、路由到实现，把结果或错误关联回原请求 | 模型生成 read_file 的名称与路径；文件内容只在工具执行后出现 | 主线 |
| 权限与运行边界 | 控制允许的操作、访问范围、人工批准；配合沙箱与资源限制 | 请求写入时停在执行之前；拒绝后文件保持原样；预算耗尽则显示停止原因 | 分支 |
| 会话、进度与恢复 | 持久记录事件、产物和检查点；恢复时重建上下文；处理长任务衔接 | 暂停后重新开始，先加载进度，再继续未完成项；当前上下文与保存的记录分开显示 | 进阶 |
| 验证、反馈与可观察性 | 接入测试或明确规则，记录调用、结果与停止原因，帮助判断质量与定位失败 | 验证器给出具体差异，结果返回模型；时间线能定位在哪次调用失败 | 分支及回顾 |

技术依据：S1/S2 支持上下文、循环、工具与运行边界；S4 支持跨会话进度与任务验收；S3/S5 支持具体反馈机制与工程约束。上述六组是教学归类，不能宣传为“所有 Harness 必须内置的六个模块”。

验证与日志也不能混为一谈：日志说明发生了什么，测试说明某条标准是否满足。二者可以是不同服务；记录了成功响应不等于验证了结果正确。运行错误同样要区分：网络短暂故障可由预设策略有限重试，任务方法错误通常要把错误交回模型再决定。不能用一个“自动修复”按钮掩盖职责。

Skills 是可按需载入的工作方法与指令；MCP 是连接工具等能力的协议；Hooks 是在运行事件触发的扩展点；子 Agent 是委派方式。它们都值得作为关联词条解释，但不应与最小循环并列成入门必修的零件。[S2]

## 先教会一个最小任务

贯穿示例：用户要求“读一下 todo.txt，告诉我还有哪两件事没做”。文件固定为三行：已完成“买咖啡”，未完成“寄快递”和“给绿植浇水”。这是教学模拟数据，不调用真实模型或读取用户真实文件。

开始时只出现用户任务、模型和文件。随着步骤推进，逐渐显露负责传递的 Harness。角色位置固定，移动的是具体请求或结果；每一步只讲一个因果关系。

| 步骤与画面主句 | 谁在做什么 | 动画与数据变化 | 应学会什么 |
| --- | --- | --- | --- |
| 1. 模型现在知道文件里有什么吗？ | 用户提交任务；Harness 接收 | 任务进入输入区；文件内容仍未送入模型 | 知道文件名不等于读到了内容 |
| 2. 把任务和工具说明交给模型 | Harness 组装本次上下文并调用模型 | 输入区显示任务与“read_file：读取指定文件”两项，然后送入模型 | 模型只能使用这次收到的信息 |
| 3. 模型提出一个读取请求 | 模型返回工具调用 | 显示 read_file(path="todo.txt")，停在 Harness 接口前 | 提出请求与执行动作是两件事 |
| 4. 工具真正打开文件 | Harness 检查并调度工具；工具读取 | 已允许的读取请求通过；文件展开三行内容，结果返回 | 工具实际接触环境，Harness 负责安排 |
| 5. 让模型看到读取结果 | Harness 追加工具结果，再调用模型 | 原输入保留，新增三行文件内容高亮；第二次调用有明确标记 | 循环之所以有效，是模型获得了新信息 |
| 6. 根据文件内容给出回答 | 模型返回两项未完成事项；Harness 结束本轮 | 文件中两行与回答逐项对应；停止传递 | 这次没有待执行工具请求，正常结束本轮；不等于任何任务均已通过验收 |

每一步提供“上一步 / 下一步”，最后可完整重播。主路径不自动跨越阅读步骤；可选自动播放属于复习模式。按钮控制的是教学时间，实际 Harness 不需要用户每轮点下一步。真实权限批准只在策略要求时出现。

步骤 3 展示结构化请求，不伪造模型内部思维链。可写“模型请求读取文件”，不写“现在我们看到了模型真实的完整思考过程”。步骤 6 的正常结束条件只描述这个成功样例；预算、取消、错误和等待用户输入另有终态。

## 再通过问题引出其他部分

在用户完成最小循环后，提供四个可逐步体验的情境。每个情境沿用同一套角色与数据流，避免换一整套视觉语言。

| 情境 | 分步演示 | 新增理解 |
| --- | --- | --- |
| 文件没找到怎么办？ | 返回 FILE_NOT_FOUND → 错误进入上下文 → 模型请求列目录 → 发现 tasks/todo.txt → 重新读取 → 回答 | 失败也是工具结果；模型依据证据改变动作。预设的网络重试单独解释，不混用 |
| 模型能随便改文件吗？ | 请求“把寄快递标为完成” → 生成写入请求 → 演示策略要求批准 → 选择允许或拒绝 → 文件变化或保持原样 | 权限位于执行之前；批准与拒绝都能走到明确终态。演示操作不访问真实文件 |
| 写完就算成功了吗？ | 给定“只改变寄快递一项”的规则 → 展示一次教学失败分支 → 验证发现浇水也被误改 → 具体差异回传 → 模型请求修复 → 再验 | 验收需要规则和证据；Harness 不天然知道正确答案，失败不是每次都必须发生 |
| 任务太长或中断怎么办？ | 标明已做与未做 → 保存会话及产物检查点 → 暂停 → 恢复时加载进度 → 继续未完成项 | 历史记录、当前上下文和磁盘产物不同；恢复外部写入还须核对实际状态，不能盲目重放 |

另在循环回顾中提供一次“停止”与“一轮预算已用完”的短演示，解释停止原因；不为每个运行选项另开一页。沙箱只需通过“本示例只允许访问任务目录”的范围说明讲清，云容器部署细节按需展开。

基础循环没有强制验收节点；进入写入分支后才显示验证器。验证由模型调用测试工具或预设流程触发都可能成立，本示例明确采用预设验收规则触发。它检验的是给定规则，不承诺穷尽所有错误。

## 桌面画面与下一轮原型约束

保留星星主页、已有选中反馈和进入词条的连续感。进入教学后，星星承担角色标记和路径定位；动作方向、传递数据、状态变化必须清楚，不能让轨道装饰影响角色归属。

词条页采用一个主讲解区域：上方一句当前问题，中部固定角色与当前请求/结果，下方步骤控制。当前上下文只在涉及模型输入时展开；完成后折叠为回顾入口。避免另设重复摘要、状态标签、营销副标题和大段小字。

页面文案保持少量，但不删去“谁做了什么、传递了什么”这两类必要解释。每步最多一句主句加一至两句说明；工具参数和文件内容属于证据，不算重复说明。颜色只辅助标识，角色名称和箭头方向始终可辨认。

下一轮应先画“同一方案的连续关键帧”：模型尚未读文件、提出读取请求、工具返回、第二次调用、正常回答，再补权限或失败分支。先检查这些画面能否组成完整讲解，再做视觉风格变体。R3 三张不同布局不承担这一验收作用。

## 教学与实施验收

内容评审先确认：读者能指出谁决定动作、谁执行动作，解释第二次模型调用为何知道更多，以及为什么结束回答不等于验收成功。可用一组简单预测题收集错误点，例如“工具刚读完文件，模型已经知道内容了吗？”正确判断依赖结果是否已回传。

后续实现必须支持前进、后退、重播及所有分支终态；回退不得残留未来步骤的数据；拒绝写入不得改动文件；重播恢复原数据；减少动态效果设置下仍可看清状态变化。动画只表现真实模拟状态转换，不用计时器先宣称成功再补结果。

本轮验证：检视官方来源与参考教程；浏览器实际走完 S8 六步并观察画面。未制作新原型、未做用户教学测试、未运行代码测试或部署；这些不能记为已通过。VBP-004 仍在研发，研究任务完成后也不代表整体需求完成。
