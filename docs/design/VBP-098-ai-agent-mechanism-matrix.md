# VBP-098 AI Agent 下一批十条词条机制差异表

本批从 `origin/main` `353aa8f2` 开始。十条词条仍然逐条研究、逐条实现、逐条 review；完成十条后才合并和发布。每个首图只呈现一个能被读者改变的机制，避免把概念画成同一张节点流程图。

| slug | 读者要回答的问题 | 特色演示 | 可改变条件 | 可见证据与边界 |
| --- | --- | --- | --- | --- |
| prompt-injection | 网页里的命令为什么能影响模型，却不能获得发送密钥的权力？ | **信任贴纸 + 透明隔离袋**：用户目标写在蓝色任务卡，网页的恶意句子从资料袋里滑出；读者把“资料”贴纸换成“指令”，红色动作卡会被提出，但权限夹上的锁仍合不上，最后把网页句子放回资料袋，摘要继续完成 | 来源标签、是否提升为指令、工具是否有写/外传权限、是否需要确认 | 读取内容与执行动作分离；错误信任最多产生待拒绝提案，`send_secret` 实际调用保持 0；不提供可滥用攻击模板 |
| tool-choice | 多个工具都能做事时，模型选择和真正执行差在哪里？ | **工具转盘 + 盖章台**：`calendar_read`、`calendar_update`、`web_search` 三张卡在转盘上，切换 auto/required/none 让指针落到不同卡；写操作卡停在“待校验”章，只有参数和权限都盖齐才离台 | 选择策略、用户意图、读/写工具、参数校验 | 选中工具不等于调用；`none` 没有工具请求，写工具缺审批时停在台上 |
| tool-result | 一段工具结果怎样改变下一句回答，而不是变成“工具说了算”？ | **库存翻页机**：库存卡片翻出结构化字段，读者把 `stock` 从 0 拨到 8 或删掉字段；回答小票只会跟着可验证字段改写，缺字段时打出“无法判断” | `stock` 值、状态码、字段缺失、来源可信度 | 原始 JSON、校验结果、回答措辞同步变化；空结果与错误结果不伪装成“无货” |
| agent-loop | 智能体为什么必须把工具回执写回状态，才知道该停？ | **维修工位计数板**：任务卡、工具回执磁贴和“已修好”指示灯在同一块板上；读者切换 200/500 回执和轮数上限，回执只在写回状态后推动下一步 | 工具回执、状态字段、完成条件、轮数上限 | 200 才点亮完成；500 进入下一轮；达到上限时明确未完成 |
| agent-orchestration | 多个子任务怎样并行，又怎样处理冲突后再合并？ | **报告拼图桌**：检索、核对、撰写是三块可移动拼图；检索与核对同时翻面，冲突标记会卡住撰写拼图，移除冲突证据后才扣上合页 | 串行/并行、依赖、冲突证据、超时 | 撰写不读取未核对证据；冲突和合并状态可见，多个模型本身不算编排 |
| retrieval | 检索返回的是候选资料，为什么不能直接当成答案？ | **磁贴抽屉 + 相关性滑轨**：查询磁贴拉开资料抽屉，关键词和语义两根滑轨改变候选排序；读者抽掉最高分但无来源的卡，答案区留下“缺证据” | 检索方式、top-k、过滤条件、来源卡、候选缺失 | 候选、分数、来源与最终引用分开；检索空集不生成确定结论 |
| prompt-caching | 重复的长前缀为什么能快，却不能把变化的用户问题一起缓存？ | **透明胶片叠印台**：固定系统说明和工具定义印在底片上，用户问题写在可替换便签；改动底片任一字就让缓存章褪色，只有命中前缀显示复用 | 前缀是否相同、插入位置、TTL、命中/未命中 | 命中只复用相同前缀；动态内容放在后缀，缓存失效条件可见 |
| model-routing | 为什么要在请求开始前按任务分流，而不是失败后才换模型？ | **分诊转盘**：简单、复杂、边界三个请求筹码落在轻量/强模型两个槽；调高质量门槛会让边界筹码换槽，旁边成本与质量刻度同步变化 | 任务特征、质量门槛、成本/延迟权重、边界样本 | 路由发生在请求前；候选模型和分流依据可见；不把分数说成模型真实概率 |
| model-fallback | 主模型 429 后，备用模型接管时哪些差异必须告诉读者？ | **接力腕带**：主模型腕带在超时/429时断开，备用模型接过请求并贴上 `fallback=429` 标签；切换到不支持 JSON 的备用模型时，接力台停在兼容检查 | 失败类型、重试次数、备用能力、输出格式 | 触发原因、降级标记和能力差异一起返回；回退不是负载均衡，也不假设等价 |
| agent-memory | 会话结束后，怎样只记住用户确认过且下次有用的一件事？ | **记忆卡抽屉**：用户把“代码用 TypeScript”卡片投入抽屉，下一次任务只抽出相关卡；读者改成 Python 或按删除键，已生成的旧回答不被回写 | 是否同意、相关性、过期时间、纠正/删除 | 写入、取回、纠正、删除各有可见结果；工作记忆和长期记录分开，不保存整段聊天 |
