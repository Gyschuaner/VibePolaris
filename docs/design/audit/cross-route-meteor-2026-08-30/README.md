# 跨页面连续星轨评审（BUG-CEC378B5）

## 结论

旧实现不合理：CSS 概念星先换位到中心，再由另一动画对象跨页，交接时出现约 72px 瞬移和明显速度归零。R4.3 改为从被点击星体直接起飞的一条连续轨迹，已消除对象交接与轨迹重算。

## 流程步骤

1. 点击前端领域并定位 CSS 星体（健康）
   - 证据：`01-source-css-star.png`
   - 优点：CSS 与同类概念处于同一星图语义中，点击目标清晰。
   - 风险：星体属于装饰性图形，按钮的可访问名称仍由 `aria-label` 提供；截图不能验证读屏顺序。
2. 点击 CSS 后跨页飞行（健康）
   - 证据：`02-flight-mid.png`
   - 优点：使用同一个覆盖层从 CSS 原位连续移动，目标页在飞行中出现，导航和星体没有断开。
   - 逐帧采样：生产构建记录到 61 个实际位移帧，路由约在 148ms 切换，最大单帧位移 14.07px，没有对象替换或大于 28px 的跳帧。
   - 风险：截图只能证明某一时刻的视觉状态，平滑性以浏览器坐标采样补充验证。
3. 星体落到 CSS 标题旁（健康）
   - 证据：`03-term-css-arrived.png`
   - 优点：覆盖层结束后由真实详情星体接管，终点偏差为横向 0.13px、纵向 0.34px，飞行层清理为 0。
   - 风险：已保留 `prefers-reduced-motion` 的直接跳转分支；截图不能单独证明系统偏好切换，需要代码与浏览器行为测试共同覆盖。

## 最高影响改动

- 删除“470ms 中心换位 + 760ms 跨页”的拼接方式。
- 路由飞行改为单条 820ms 三次贝塞尔 motion path，只计算一次轨迹与缓动。
- 当前领域的详情路由提前预取，页面在飞行开始约 120ms 后发起导航。
- 固定滚动条槽位，防止首页和详情页宽度变化导致终点横向漂移。

## 证据限制

当前 in-app Browser 不提供移动视口调整接口，因此本轮动态逐帧采样为桌面视口；移动端几何分支、42px 落点和 reduced-motion 由结构测试覆盖，仍需在可调整视口的浏览器补一次 390×844 实机动态回归。
