# 跨页流星拖尾逐帧评审

## 范围

评审首页“前端 → CSS”跨路由飞行中的拖尾连接、方向、显隐与降级行为。浏览器证据来自本轮本地生产构建，不复用旧截图。

## 结论

旧实现的问题不在星体路径，而在拖尾素材的容器比例与锚点：正方形遮罩放进 128×78 的 `contain` 容器后产生留白，可见端点又不在 `right center`，导致拖尾偏离或消失。修复后改用项目已有的 32 帧精灵图，并用最终帧的真实端点作为变换锚点；额外旋转 45°，让尾部落在 motion path 切线后方。

## 流程与健康度

1. `01-source.png`：前端星图起点。健康度：正常；CSS 星体和可点击区域清晰。
2. `07-before-concurrent-300ms.png`：旧实现飞行中段。健康度：异常；画面只有星体，拖尾不可辨认。
3. `09-after-240ms.png`：精灵图端点锚定后、方向补偿前。健康度：仍异常；拖尾已经连接星体，但位于飞行方向侧后方，说明素材自身斜向需要补偿。
4. `15-after-direction-650ms.png`：加入 45° 补偿后的落点前状态。健康度：正常；拖尾末端与星体重叠，并位于飞行切线后方。
5. 术语页稳定态：健康度正常；覆盖层被移除，详情页标题星恢复显示。

## 开源方案比较

- Motion（MIT）的 `layoutId` 与 `arc()` 适合共享元素和弧线路径，但不直接生成拖尾。
- PixiJS Particle Emitter（MIT）可按上一帧发射器位置插值粒子，但引入 Canvas/WebGL 渲染链路对单个品牌动效过重。
- View Transition 是页面快照过渡，难以单独控制这条可中断的品牌轨迹。

因此保留原生 CSS Motion Path，只修复现有精灵图的逐帧展开与几何锚定，不新增运行时依赖。

## 可访问性与证据限制

`prefers-reduced-motion: reduce` 会隐藏跨页飞行层并直接导航，避免强制位移动效。截图只能证明视觉状态，不能单独证明屏幕阅读器、键盘焦点或所有刷新率下的表现；语义和 reduced-motion 分支由现有结构测试覆盖。本轮浏览器无法调整移动视口，移动端动态实机仍是后续回归项。
