# VibeHub CSS 与 VibePolaris CSS 词条页对比审计

## 审计范围

- 对照页面：`https://vibe-hub.org/css?q=Css` 与 `http://localhost:3000/terms/css?v=audit-compare`。
- 用户目标：快速理解一个技术术语，知道它解决什么、为什么会出问题、应该怎样让 AI 修改，并自然进入下一条学习路径。
- 桌面视口：1265×720；手机视口：375×844。两套页面均无横向溢出。
- 当前审计覆盖首屏、互动解释器、选择题、Prompt、后续学习与手机端重排；不代表完整 WCAG 合规测试。

## 流程步骤与健康度

1. 进入词条并建立基本理解：VibeHub 良好，VibePolaris 良好但内容偏薄。
2. 通过示例理解机制：VibeHub 优秀，VibePolaris 优秀但教学目标不同。
3. 用题目验证并生成 AI 指令：VibeHub 优秀，VibePolaris 基础可用。
4. 决定下一步学什么和验证来源：VibeHub 良好但夹带推广，VibePolaris 偏弱。
5. 手机端阅读与操作：两者可用；VibeHub 导航过密，VibePolaris 正文层级过大。

## VibeHub 的好处

- 把 CSS 放进一个明确的排错情境：主题按钮被灰色样式覆盖。读者不是只看定义，而是在解决问题。
- 三个互动状态形成完整因果链：基础规则、发生覆盖、修正规则；中间 `Computed` 区域说明最终值为什么变化。
- 定义覆盖选择器、优先级和书写顺序，后续还有“浏览器怎样计算”和职责边界，机制解释完整。
- 选择题继续沿用同一排错情境，正确答案会给出原因，不只是显示对错。
- 后续术语有明确顺序，并提供 MDN 权威出处；对于大规模词条库，可信度和学习路径都更强。
- 全局搜索、收藏、语言和主题入口齐全，适合规模较大的术语库。

## VibeHub 的代价

- 桌面和手机导航都偏满；375px 下多个导航项只有约 32–34px 高，清除搜索只有 22×22px，存在目标过小风险。
- 首屏定义信息很完整，但移动端是一整段连续文字，扫读成本高。
- 白底、蓝色强调、圆角面板和大量细边框较接近通用文档产品，品牌辨识度弱于 VibePolaris。
- 推荐工具区打断纯学习路径，也可能让用户怀疑内容是否受推广影响。
- 互动解释器依赖用户主动切换；状态正确但缺少 VibePolaris 那种“代码改在哪里”的连续引导。

## VibePolaris 的好处

- 暖米白、苔藓绿、黄绿色星体和流星体系形成稳定品牌语言，视觉上更有自己的味道。
- 页面比 VibeHub 安静，手机端主动收起多数导航，阅读入口更集中。
- 当前代码映射动效直接把代码行与页面目标关联；自动播放、点行暂停、继续和重播对初学者非常直观。
- “没有 CSS / 基础样式 / 响应式布局”覆盖三种观察角度，能快速建立 CSS 负责呈现与响应式的总体心智模型。
- Prompt 明确限制不改 HTML 和现有功能，并提供复制操作，任务边界清楚。
- 相关术语复用星点语言，与首页星图和跨路由流星体验一致。

## VibePolaris 的短板

- 当前例子是背景、标题、导航和留白的四个并列变化，没有一条贯穿的因果故事；用户能看到“改了哪里”，但还不知道“为什么这条生效、那条被覆盖”。
- 定义过于简化，没有讲选择器、层叠、优先级、书写顺序和 computed style；对于 CSS 这个核心术语不够完整。
- 判断题只区分 CSS / HTML / JavaScript，难度过低，不能证明用户真的理解了 CSS 排错。
- “继续探索”的四个词同权，没有前置、下一步或推荐原因；对于未来 1000+ 词条，容易变成随机跳转。
- 没有权威来源和最近校验信息，不利于大规模词条的准确性与信任。
- 375px 下核心定义为 27px / 41.85px 行高，单句占 126px；品牌很强，但把互动解释器推得更靠下。
- 手机端主题、Markdown 复制和朗读按钮分别约 32px、41×35px、38px，仍有小于 44px 的点击区域。

## 最值得吸收的混合方案

保留 VibePolaris 的视觉和动态机制，但把内容骨架换成 VibeHub 的因果教学：

1. 首屏仍保持当前品牌结构，只把“你可能会说”改成一个真实症状，例如按钮颜色被覆盖。
2. 互动区继续使用左侧代码、右侧页面的 VibePolaris 形式，但三阶段改为“基础规则 → 发生覆盖 → 修正规则”。
3. 在右侧页面和状态栏之间增加一个极简 `Computed` 条，只显示最终属性值和来源规则；不新增大段灰字。
4. 动效仍逐行映射，但每一步都服务于同一因果故事：加入规则、按钮变灰、定位来源、修正并恢复。
5. 互动区下只保留两组短说明：“浏览器怎么决定”用 `匹配 → 层叠 → 最终值` 三步表达；“别混淆”用一句话区分 CSS / HTML / JavaScript。
6. 判断题升级为排错题，反馈说明为什么；Prompt 同时要求检查命中规则和 computed style，并保留现有结构/功能边界。
7. 把四张同权相关卡改为“两条推荐路径 + 周边概念”：优先选择器、层叠/优先级，再提供盒模型与响应式布局。
8. 页尾增加 1–3 条权威来源和最近校验日期；不吸收工具推广模块。
9. 恢复一个低噪全局搜索入口，用单个 44px 搜索图标或快捷键打开覆盖层，不照搬整条搜索框。
10. 手机端把定义降到 23–24px、行高约 1.45，并把主题、复制、朗读点击区扩到至少 44px。
