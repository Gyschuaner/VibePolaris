# VBP-099：模型内部与部署机制十条设计记录

本批从 VBP-012 的公开词条里新增十个仍缺少读者入口的模型机制。每条先回答一个小问题，再用一个只改变关键条件的可观察场景把边界呈现出来。演示类型刻意分散：本批只有投机解码需要有限的先后关系；束搜索用候选对照，其余使用刻度盘、影子课堂、分诊台、温度计、封存柜、陌生件验收台、适配器磁贴和模型卡折页。

## 资料与改写边界

每条页面的 `lib/ai-stack-concept-sources/model-mechanisms.ts` 都保留四条以上实际参考资料，正文段落用 citation id 映射回对应来源。研究时只把来源明确支持的机制写进定义，不把某篇论文的速度、压缩率或实验设置扩写成普遍保证：

- 量化区分训练后量化和量化感知训练；GPTQ、AWQ 的结果只作为方法实例，不把单一硬件上的加速数字当成通用承诺。
- 知识蒸馏保留教师输出的软目标与学生模型的训练关系；DistilBERT、TinyBERT 是案例，不代表所有蒸馏都采用相同损失。
- 混合专家强调稀疏激活、路由、容量和负载平衡；专家数量与 top-k 是实现选择，不是概念定义。
- 投机解码区分草稿模型与验证模型；接受草稿可以保持目标分布，但速度收益取决于匹配率和硬件。
- 束搜索是候选保留策略；更高分只说明模型评分更高，不能替代事实核验。
- 置信度校准把概率和长期正确率对齐；校准曲线本身不解决分布变化和错误标签。
- 数据污染先问评测样本是否在训练资料里出现，再谈分数；检测并不总能证明没有泄漏。
- OOD 先标记训练分布之外的样本；最大 softmax 概率等基线可能失效，拒答需要单独的阈值和业务策略。
- PEFT 只更新少量参数；适配器较小不代表任务一定学会，也不等同于基座模型权限改变。
- 模型卡记录适用范围和限制；有卡片不代表模型安全或适合任意场景。

## 旧词条流程视觉审计

当前 `term-experiences` 共 339 条，其中真正使用箭头流向的 `route`、`pipeline`、`loop` 三类共 50 条（约 14.7%）；`branch` 另按条件面板呈现，不再自动画成流程箭头。本批十条使用量化光谱、课堂分层、专家矩阵、草稿回滚、束宽对照、可靠性光谱、封存契约、分布外检验、适配器装配和发布卡契约等独立空间语法，只有投机解码保留“草稿→验收→接受/回滚”的关系线，没有新增通用流程图。这一比例不是新的模板要求；它是现存数据的审计结果。后续批次把这 50 条逐条复核，只有概念确实表达有序交接时才保留 flow scene，其余改成 `compare`、`layers`、`matrix`、`contract`、`state-machine` 或专属场景，并同步改写 frames 的观察对象和停止证据，而不是只换一个标签。
