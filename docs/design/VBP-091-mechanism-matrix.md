| 词条 | 读者要判断的机制 | 初始对象 | 关键操作 | 可观察证据 | 特有边界 |
| --- | --- | --- | --- | --- | --- |
| safe-area | 背景可以铺满屏幕，关键内容要读动态 inset | 带刘海和手势条的手机活动页 | 读取安全距离，再切换横屏 | 标题与按钮从危险边界移入，横屏改为左右 inset | 不是固定 20px；背景和可操作内容处理不同 |
| app-lifecycle | 进后台、冻结和进程回收对状态的影响不同 | 前台编辑器、内存页面、持久化草稿 | 进入后台并模拟进程消失，再重新打开 | 内存状态消失，页面从已保存快照重建 | 回调不是可靠的最后保存机会，不能把恢复当成原进程继续 |
| app-permission | 用户任务、用途说明和系统决定之间的责任边界 | 拍照上传任务、权限闸门、替代上传 | 选择允许或拒绝，并重播请求 | 允许打开相机，拒绝走文件上传 | 平台状态和再次请求规则不同，声明不等于运行时获准 |
| push-notification | 令牌、推送服务、系统展示和点击核验是不同结果 | 设备令牌、服务器事件、推送服务、通知栏 | 切换有效/过期令牌并发送订单变化 | 有效令牌到达通知，过期令牌收到失败回执并清理 | 投递成功不等于展示或点击；令牌会刷新 |
| cross-platform-development | 共享规则与平台能力应在边界处分开 | 共享订单核心、iOS 适配器、Android 适配器 | 在清楚/越界边界之间切换 | 业务规则保持一致，平台 API 各自执行；越界时核心被污染 | 共享比例不等于行为完全相同，权限和硬件仍需平台验证 |
| webview | 网页消息不是任意原生调用，宿主必须校验 | WebView 页面、消息桥、原生分享 | 切换受信/未知来源，经过来源、方法和参数检查 | 受信页面打开分享，未知来源被挡在桥外 | WebView 不是完整浏览器；宿主不能把任意页面接到任意 API |
| css-selector | 选择器先找出匹配 DOM 节点，之后才进入层叠 | 五个不同结构和属性的 DOM 节点 | 逐步增加 class 与属性条件 | 匹配集合由 3 个收窄到 1 个，最终样式仍未被假定 | 命中不等于生效，层叠和特异性仍是后续步骤 |
| box-model | content、padding、border、margin 分别占哪一层空间 | 嵌套的盒子区域与 width: 200px | 逐层加入 padding/border，再切换 box-sizing | content-box 外框变 234px，border-box 外框保持 200px | margin 不在 border box；布局上下文还会继续影响尺寸 |
| cascade | 来源、层和重要性先筛声明，后面才比较优先级 | 三张规则牌：UA、base 层、theme 层 | 推进牌堆并切换普通/`!important` | 普通声明由 theme 层胜出，重要声明翻转到 base 保护规则 | “后写覆盖前写”只在前置条件都相等时成立 |
| specificity | 相同来源和层内，选择器按 ID/类/元素三列左到右比较 | 两条实际选择器与三列计数盘 | 对比普通选择器、`:where()`、`:is()` | 明确哪一列先分出胜负，`:where()` 归零、`:is()` 取最高 | 优先级不负责命中、来源或层；继续堆 class 不能越过前置比较 |

## 共用实现约束

- 首图采用紧凑机制画布，不把线性步骤卡作为唯一表达；每页的主体对象、空间关系和失败分支不同。
- 播放、暂停、推进、重播和 `prefers-reduced-motion` 沿用 `useScene` 与 `SceneControls`；切换分支会重置本轮进度。
- 桌面首图与正文共用阅读宽度，390px 窄屏不产生横向溢出；分支控件有名称、状态和键盘焦点。
- 本批正文与来源台账已存在，研究来源按词条分别保留在 `content/zh/term-experiences/frontend-product.json`；本轮不改正文、来源、锚点和相关词条关系。
