# VBP-089 产品与技术基础词条机制差异表

这批先处理十个仍使用通用数据演示或旧流程首图的词条。每条先写清读者要看见的机制，再决定首图的物件、动作和终态；首图保持紧凑，放在标题旁边，正文负责完整解释和边界。

| 词条 | 读者卡住的原话 | 初始对象 → 操作 | 可见证据与停止条件 | 首图构图/交互差异 | 资料锚点 |
| --- | --- | --- | --- | --- | --- |
| runtime | “同一段 JavaScript 为什么在浏览器能跑，换到 Node 就缺东西？” | 同一段代码卡片 → 切换执行环境 | 可用 API 集合改变；停在“`document` 可用/`fs` 可用”的边界，不把环境差异说成代码自动修好 | 双面环境舱：浏览器侧 DOM 插槽、Node 侧文件插槽，代码卡片翻面后只接入对应插槽 | [MDN JavaScript environments](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Introduction)、[Node.js Introduction](https://nodejs.org/en/learn/getting-started/introduction-to-nodejs)、[Node.js Globals](https://nodejs.org/api/globals.html)、[MDN Web APIs](https://developer.mozilla.org/en-US/docs/Web/API) |
| package | “`^2.3.0` 到底锁住了什么，为什么还要 lockfile？” | 版本范围标签与依赖树种子 → 拨动解析日期 | 间接依赖节点变成不同精确版本；停在锁文件摘要与完整性值，不显示“锁了就安全” | 依赖树像可旋转的齿轮盘，范围环先松后收，锁文件像压在树上的印章 | [npm package.json](https://docs.npmjs.com/cli/v11/configuring-npm/package-json)、[npm package-lock.json](https://docs.npmjs.com/cli/v11/configuring-npm/package-lock-json)、[npm semver](https://github.com/npm/node-semver)、[npm workspaces](https://docs.npmjs.com/cli/v11/using-npm/workspaces) |
| typescript | “类型检查通过，是不是运行时就一定不会出错？” | 带类型注释的输入 → 点击检查，再切换真实 JSON | 编辑器的红线消失但运行输入仍可变；停在“静态保证边界”与“运行时校验”并排可见 | 一张半透明的类型尺压过代码，外部 JSON 从尺下穿出，只有加校验才进入安全槽 | [TypeScript Handbook](https://www.typescriptlang.org/docs/handbook/intro.html)、[Everyday Types](https://www.typescriptlang.org/docs/handbook/2/everyday-types.html)、[Narrowing](https://www.typescriptlang.org/docs/handbook/2/narrowing.html)、[strict](https://www.typescriptlang.org/tsconfig/strict.html) |
| mvp | “最小可行是不是只做半成品？” | 产品假设卡与功能筹码 → 拿走非关键筹码 | 关键任务仍可完成并留下验证信号；停在“学到什么”而不是“做了多少” | 假设靶盘：筹码被拿走后，唯一一条真实任务线仍可点通，结果落到证据槽 | [GOV.UK MVP](https://www.gov.uk/government/publications/nuar-minimum-viable-product-mvp/nuar-minimum-viable-product-mvp)、[GOV.UK prototyping](https://design-system.service.gov.uk/get-started/prototyping/)、[Nielsen Norman Group MVP](https://www.nngroup.com/articles/minimum-viable-product/)、[Lean UX](https://www.oreilly.com/library/view/lean-ux-3rd/9781098136827/) |
| user-flow | “流程图画完了，用户迷路时怎么办？” | 任务卡、入口和返回票 → 选择失败分支 | 过期链接回到原任务，成功与失败都能落到明确终态；停在“可回来”的恢复点 | 一张可折叠的纸带，入口和结果在两端，过期票据从中间掉落并回到原任务，不画横向节点流水线 | [GOV.UK service manual](https://www.gov.uk/service-manual/user-research)、[Nielsen Norman Group user flows](https://www.nngroup.com/articles/user-flows/)、[Material Design navigation](https://m3.material.io/foundations/interaction/navigation)、[W3C WCAG error recovery](https://www.w3.org/WAI/WCAG22/Understanding/error-prevention-legal-financial-data.html) |
| wireframe | “线框图是不是没上色的最终稿？” | 一张空白页面纸 → 抽出内容、关系、操作层 | 去掉颜色仍可判断结构和操作；停在低保真边界，不假装验证视觉与响应式 | 纸张被掀开四个结构窗口，内容块的大小和顺序可拖，颜色层始终保持缺席 | [GOV.UK prototyping](https://design-system.service.gov.uk/get-started/prototyping/)、[Figma wireframes](https://help.figma.com/hc/en-us/articles/360040314193-Wireframes)、[Nielsen Norman Group wireframes](https://www.nngroup.com/articles/wireframes/)、[GOV.UK Service Manual](https://www.gov.uk/service-manual) |
| ia | “内容放进菜单后，用户怎么知道去哪里找？” | 孤立内容卡与任务词 → 拖入语义区域并选入口 | 同一内容从两个任务入口被找到，但只保留一份正文；停在可预测入口与单一来源 | 磁性标签板：内容卡不是沿箭头走，而是被用户任务词吸附到区域，入口标签从侧面亮起 | [GOV.UK information architecture](https://www.gov.uk/service-manual/design/information-architecture)、[Nielsen Norman Group IA](https://www.nngroup.com/articles/information-architecture-ia/)、[W3C design patterns](https://www.w3.org/WAI/ARIA/apg/)、[GOV.UK navigation](https://design-system.service.gov.uk/components/header/) |
| prototype | “可点击原型是不是已经证明产品能上线？” | 一张假设卡与任务脚本 → 让测试者走一格并记录停顿 | 停顿/误解成为证据，模拟部分仍标注为模拟；停在下一轮决定，不显示上线勾 | 观察台：同一条任务胶片经过“假设—操作—停顿—决定”四个窗口，停顿会留下可移动标记 | [GOV.UK prototyping](https://design-system.service.gov.uk/get-started/prototyping/)、[Nielsen Norman Group prototype](https://www.nngroup.com/articles/prototype/)、[GOV.UK service manual user research](https://www.gov.uk/service-manual/user-research)、[IDEO Design Kit](https://www.designkit.org/methods/prototyping) |
| design-system | “组件库很多，为什么还叫设计系统？” | 一个按钮样本与规则卡 → 切换 token/组件/治理层 | 同一 token 改变多个实例，并能看到规则与迁移记录；停在可维护的一致性，不是画廊 | 织布机：token 是经线，组件是织片，治理针脚连接版本与迁移；拖动色票会同步两个实例 | [GOV.UK Design System](https://design-system.service.gov.uk/get-started/)、[Material Design system](https://m3.material.io/foundations)、[IBM Carbon](https://carbondesignsystem.com/guidelines/overview/)、[Figma variables](https://help.figma.com/hc/en-us/articles/15339657135383-Guide-to-variables-in-Figma) |
| a11y | “加了 ARIA 就无障碍了吗？” | 表单字段、错误和焦点 → 只用键盘提交错误 | 焦点回到有错误字段，名称/顺序/文字仍可读；停在可感知、可操作、可恢复，不把颜色当唯一信号 | 键盘钥匙串：焦点环沿真实控件移动，错误标签像磁贴贴回字段，而不是画一条流程线 | [W3C WCAG 2.2](https://www.w3.org/TR/WCAG22/)、[WAI-ARIA APG](https://www.w3.org/WAI/ARIA/apg/)、[GOV.UK error message](https://design-system.service.gov.uk/components/error-message/)、[MDN accessibility](https://developer.mozilla.org/en-US/docs/Web/Accessibility) |

每个组件都复用已有的播放、暂停、重播、可见区域暂停和减少动态能力，但只复用生命周期，不复用同一套画面。每条词条单独实现、检查和提交；十条全部完成后才统一更新 rollout 台账、走评审和发布。
