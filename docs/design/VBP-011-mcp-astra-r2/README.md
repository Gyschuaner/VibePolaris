## 教学主线与场景契约

读者会浏览网页和与 AI 聊天，没有编程经验。遇词入口为“添加 MCP 服务器”。目标是能够解释为什么应用与服务需要共同约定、没有 MCP 如何接入，以及为什么连接成功不代表拥有任意能力。

本轮使用虚构青禾图书馆的借阅指南。先用三段常驻正文讲清取得工具说明、发出查询、取回资料进入回答，再互动；接着讲没有 MCP 时的专门接入和 MCP 可复用的部分，最后引入角色、配置、资源、模板及边界。

- 初态：两个支持 MCP 的应用；固定同一资料服务和指南；当前应用未连接，没有工具说明或本轮结果。
- 连接并发现：工具说明在应用内出现，包括名称、用途、输入；尚未查询。
- 发请求：带关键词的卡片到服务一侧；没有借期结果或模型回答。
- 服务查询并返回：卡片向应用移动，显示借期 30 天和来源；再由独立操作生成固定回答。
- 换应用：服务与资料保持不变，新应用重新发现同一说明；已有查询单独标为“上次取得”并保留来源应用。
- 断开：清除当前连接和本轮流程，保留上次结果；未模拟数据修改。完整重置才清除全部状态。为避免中途断开被误解成取消已发请求，演示请求阶段禁用切换和断开，仍允许明确的全场景重置。
- 本体演示手动推进，无后台计时器；共享首图只做有限入场，在离屏/后台暂停。CSS 保留进出过渡与减少动态偏好。
- 验收范围：build、本页桌面/390px、阶段/换应用/断开/重置、引用/术语卡片与适用键盘；不扩展整站回归。
