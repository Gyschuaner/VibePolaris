# VBP-012 下一批 AI 交互词条机制差异表

本批从最新 `origin/main` 开始，按词条逐条研究、写作、实现和审阅；十条完成后才统一集成。资料与现有词条的引用台账一一对应，演示使用固定教学数据，不调用真实模型或用户数据。

| slug | 读者要回答的问题 | 首图 / 互动机制 | 可改变条件 | 可见证据与停止条件 |
| --- | --- | --- | --- | --- |
| streaming-output | 为什么看到第一句话还不能说响应已经完成？ | **收据卷轴**：一张配送收据从打印口逐段吐出；文字片段落在纸带上，最后的“完成章”只有在服务端发来的结束标记到达后才盖上。中断时纸带停在半句并保留红色断口 | 正常结束、流中错误、空文本、取消读取 | 片段、文字结束、完成章和错误分层；停止本地读取不等于服务端已完成或结果已保存 |
| structured-output | 字段形状正确，为什么金额仍可能错？ | **模具压印台**：在本例 `amount: integer` 且禁止额外字段的 schema 下，候选数字放入模具，字符串和多余字段被校验拒绝；合规票据仍要与原始金额卡核对 | 字段规则 schema、只要求可解析 JSON、纯自然语言；120/999/字符串/缺字段 | 格式通过与事实通过分开；截断、拒绝和空结果不生成伪造对象 |
| function-calling | 模型写出函数名后，哪一步才真的碰到订单？ | **柜台取号牌**：模型递出带一个调用编号（本例写作 `call_id`）的取号牌，应用按本地注册表和权限策略检查后才打开订单柜；结果带同一编号返回 | 已注册/未注册、参数合法性、查询权限、订单是否存在 | 请求出现不等于执行；执行次数和业务结果分别显示 |
| plan-and-execute | 执行中的一步失败后，为什么计划要改而不是继续往下跑？ | **施工蓝图覆膜台**：规划器先把可执行步骤压在蓝图上；执行器遇到失败时把后继磁贴锁住，规划器插入修复和复测磁贴，测试/部署只是本例场景 | 失败节点、修复是否插入、轮数上限 | 后继步骤被锁住；修复与复测通过后才解锁部署 |
| handoff | 交给专家后，下一条消息由谁处理？ | **值班胸牌换柜**：客服胸牌取下，退款专家领取带目标、已完成事实、待办和限制的交接卡；缺订单号时胸牌退回客服，交接只转责任，不执行退款 | 交接包完整性、专家是否接手、是否退回 | 当前责任人和交接包内容可见；缺事实或循环时停止 |
| human-in-the-loop | 人怎样在高风险动作发生前改变结果？ | **退款封条**：退款单被红色封条压住，审阅者在封条上盖批准、改额或拒绝；只有批准后的单据才穿过执行槽 | 批准、改额、拒绝、超时 | 执行前保持无副作用；超时保持待审（本例按拒绝处理），改额后重新等待批准，决定与具体调用绑定 |
| guardrail | 规则命中后，系统到底放行、改写还是阻断？ | **出闸扫描门**：客户表经过扫描门，手机号字段被框出；读者拨动处置拨片，纸条被遮罩或卡在闸门前。guardrail 检查内容或工具输入输出，不等于身份授权 | 脱敏/阻断、输入/输出/工具检查位置、检查器故障 | 本例采用检查失败即阻断；产品也可能选择告警或降级，必须明示策略，权限仍由另一层检查 |
| moderation | 审核模型给出的风险分怎样变成产品动作？ | **分拣传送带**：三条评论沿传送带经过分类器色标，产品阈值拨片移动时它们进入展示、复核或隐藏筐；moderation 分队列，不负责工具授权 | 阈值、评论分数、人工复核容量 | 分数、队列和处置分离；分数不是法律结论 |
| fine-tuning | 训练越久，怎样判断模型没有只记住训练样本？ | **两块曲线板**：训练损失曲线继续下降，验证集指标在这个过拟合示例中先变好后恶化；读者拖动训练轮数，验证恶化时停止并选最佳检查点。这里的曲线不是每次训练必然形状 | 训练轮数、训练/验证曲线、最佳检查点 | 训练与验证分开；验证指标恶化时明确停止追加训练；提示词和检索解决的是不同问题 |
| working-memory | 智能体怎样只留下当前任务需要的临时状态？ | **可擦写任务桌**：预算、候选和库存回执以磁贴放在桌面；回执回来才擦掉无货项，交付后只清理预算/候选/回执草稿；长期偏好另存到长期存储区，本轮任务桌不会自动带入 | 回执是否返回、候选筛选、交付与清理 | 未知保持未知；交付物和临时状态生命周期分开，working memory 不等于数据库或长期记忆 |

## 共同验收

- 每条有自己的对象、操作和证据，不用同一条“输入 → 处理 → 输出”流程替换十个概念。
- 初态、关键条件变化、失败或等待状态、稳定终态都可读；重置不会沿用上一轮结果。
- 首图保持紧凑，主体演示不依赖大段脚注；390px 视口与 `prefers-reduced-motion` 保留信息和操作。
- 每个正文论断对应已实际阅读的公开来源，引用目标和来源台账保持同步。
