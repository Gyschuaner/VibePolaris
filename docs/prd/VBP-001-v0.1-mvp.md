## 1. 背景与定位

Vibe coding 用户有两个高频卡点：

1. **不会说**：心里想要某个东西，却不知道它的准确名称，向 AI 描述时词不达意（"就是那个……点一下会弹出来的小框"）。
2. **不会选**：面对模型、编程工具、技术栈不知道选哪个，也不知道该向 AI 提什么约束。

VibeHub 已把"大白话 → 准确术语"的图鉴范式验证成功（281 条目、中英双语）。VibePolaris（Polaris = 北极星）沿用这一已验证范式作为地基，主打差异化：**"指北" = 替用户把选择做好** —— 不止告诉你这个词叫什么，还告诉你该怎么选、怎么选、选完怎么向 AI 表达。

**一句话定位**：一个帮你「把大白话翻译成准确术语、并替你指路选型」的 Vibe Coding  companion 站点。

## 2. 目标用户

| 用户 | 典型场景 |
| --- | --- |
| 纯小白 / 非工程师 | 用自然语言指挥 AI 做产品，遇到看不懂的术语和报错名词 |
| 半专业独立开发者 | 用 AI 提效做独立产品，选型纠结（模型、框架、托管） |
| 专业开发者 | 快速查证概念边界、了解 AI 编程工作流术语 |
| 产品经理 / 设计 | 需要与 AI 或研发准确沟通需求措辞 |

四类用户共用一套内容，条目写作口径以"小白能懂、专业不嫌浅"为准：大白话示例服务前者，准确定义与关联关系服务后者。

## 4. 信息架构与页面清单

```
/                 首页：价值主张 + 搜索框 + 六大分类入口 + 选型指南置顶卡
/[locale]/terms              术语浏览页：左栏分类/子分类，右侧条目卡片流，顶部搜索
/[locale]/terms/[slug]       术语详情：基础四件套 + Prompt 模板 + 关联术语 + 路线阶段
/[locale]/guides             选型指南列表
/[locale]/guides/[slug]      选型指南详情（首发：AI 模型/编程工具选型）
/[locale]/tools              工具/资源导航：标签筛选 + 列表
/[locale]/about              关于页（含 roadmap 占位，指向后续模块）
```

- `locale` 首发仅 `zh`（无前缀直达），路由结构按 `[locale]` 组织，`/en` 返回 404 但 hreflang 结构预留。
- 导航栏：术语 / 选型指南 / 工具 / 关于 + 主题切换 + 搜索（`⌘K` 或点击）。

## 5. 内容设计

### 5.1 术语条目范式（基础四件套 + 两项增强）

以 VibeHub 范式为基础，每条必含：

1. **中英文名**：如 `按钮 Button`
2. **大白话需求示例**：第一人称口语，如 "帮我加个按钮，点了就能把内容存下来。"
3. **一句话准确定义**
4. **所属分类 / 子分类**
5. **可复制 Prompt 模板**：直接可用、含占位符的提示词
6. **关联术语 + 路线阶段标记**（stage 1/2/3 = 起步 / 进阶 / 熟练）
7. （可选）`synonyms` 同义词/别名，用于大白话搜索加权

### 5.2 首发 20 条术语规划

| 分类 | 条数 | 条目 |
| --- | --- | --- |
| 前端 | 4 | 组件 Component、状态 State、响应式布局 Responsive、表单 Form |
| 后端 | 3 | API、数据库 Database、认证 Authentication |
| AI·Agent | 5 | 大模型 LLM、提示词 Prompt、上下文 Context、Token、智能体 Agent |
| 技术栈 | 3 | 框架与库 Framework vs Library、静态站点与服务器渲染 SSG/SSR、部署与托管 Deploy |
| Git | 2 | 仓库与提交 Repo & Commit、分支 Branch |
| 产品与设计 | 3 | MVP、用户流程 User Flow、线框图 Wireframe |

20 条定位为"定框架的骨架内容"：把分类体系、条目 schema、搜索与展示链路全部跑通，后续扩充只加内容文件、不改代码。

### 5.3 选型指南范式

```
场景描述（"我想做 X"）→ 关键约束（会/不会写代码、预算、上线速度）
→ 候选对比表（定位/适合谁/代价）→ 推荐结论（默认选择 + 何时换）
→ 向 AI 的说法建议（复制即用）
```

首发篇目：《AI 模型 / 编程工具怎么选》——覆盖 Claude / GPT / DeepSeek / Gemini 等模型与 Cursor / Codex / Lovable / v0 / Bolt 等工具的定位与适用场景（内容需注明"更新于"日期，选型时效性强）。

### 5.4 工具导航范式

每条：名称 + 一句话定位 + 标签（如 `代码编辑器` `对话模型` `生成式建站` `托管部署`）+ 官网链接 + 免费额度说明。首发 15～20 条。

## 6. 内容工程（Git 即 CMS）

- 目录：`content/zh/terms/*.md`、`content/zh/guides/*.md`、`content/zh/tools/*.json`；分类定义 `content/taxonomy.json`
- 术语/指南用 Markdown + frontmatter（字段见 5.1），工具导航用 JSON
- 构建时校验（zod）：缺必填字段的条目构建失败并明确报错，防止半成品上线
- 新增一条内容 = 新增一个文件，零代码改动；`status: draft` 的条目本地可见、构建产物剔除

## 7. 非功能需求

| 项 | 要求 |
| --- | --- |
| 技术栈 | Next.js（App Router，SSG 优先）+ TypeScript + Tailwind CSS |
| 主题 | 亮/暗双主题，CSS 变量；默认跟随系统，手动切换持久化 localStorage；视觉母题：北极星/夜航指北（亮色靛蓝系、暗色星空蓝） |
| 搜索 | 客户端全文检索（Fuse.js / FlexSearch），字段权重：同义词 > 大白话示例 > 名称 > 定义 |

| 性能 | Lighthouse Performance / SEO ≥ 90；首屏无 JS 也可读（搜索与主题切换渐进增强） |
| 无障碍 | 键盘可达、对比度达标、语义化标签 |
| 部署 | Vercel；`main` → 生产预览隔离按 AGENTS.md 分支模型执行；域名 `vibepolaris.chuansgu.top`（DNS 未就绪，先用 Vercel 默认域名验证） |

## 10. 风险与对策

- **选型内容时效性**：每篇指南带"更新于"标记，超过 90 天在页面顶部提示"信息可能过时"。
- **20 条太少显得单薄**：用"框架先行、每周扩充"的公开 roadmap 管理预期；首页显示条目数随构建自动更新。
- **DNS 未就绪**：Vercel 默认域名先行验收，域名绑定作为独立后续任务，不阻塞验收第 8 条之外条款。
