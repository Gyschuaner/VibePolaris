# 验收标准

在实现前选择适用范围，交付前核对结果。清单定义“什么算完成”，不意味着每个小改动都要跑完整套测试。项目根目录 `AGENTS.md` 对验证、DP 记录和交付阶段的要求优先。

## 先确定验收范围

| 改动 | 最小有意义的检查 |
| --- | --- |
| 新增独立概念页 | 事实与引用、无动画通读、机制差异、构建、受影响交互的桌面和窄屏真实浏览器检查 |
| 只改演示 | 构建；状态顺序、输入变化、退出/重置；涉及的键盘与窄屏表现；不重测未改的全站星图 |
| 只改排版 | 构建；发生变化的断点、最长内容和展开状态；无须新增自动化用例 |
| 只改文案或来源 | 核对文字和论断对应关系；影响构建输入则按项目规则构建；只有改动影响布局、锚点或交互时增加对应浏览器检查 |
| 只维护本 Skill | 检查 frontmatter、内部链接、组件入口与说明一致性；不运行应用构建、整站回归或部署 |

桌面使用正常阅读视口；手机选一个有代表性的窄视口，例如 390px。若新增了独立大屏布局，检查该断点即可；不为了形式穷举所有设备。验证后恢复临时视口设置。

## 内容与事实

- [ ] 读者不播放演示、不展开补充内容，也能解释定义、因果过程和主要边界。
- [ ] 来源实际读过且支持对应论断；厂商接口、研究方法、示例简化未被写成无条件通用事实。
- [ ] 教学输入、操作、结果前后一致；固定样例没有声称真实访问用户文件、调用模型或完成任意任务。
- [ ] 标题对应正文，无连续营销式设问；段落有具体主体和动作，重点加粗有明确理由。
- [ ] 正文角标与书目编号一致，来源能返回正确段落；无缺失 ID、空摘录或陈旧的手写副本。

## 演示是否表达了这个概念

- [ ] 操作会改变有意义的对象、位置、内容或状态，读者看得出变化依据；不只更新说明文字或图标颜色。
- [ ] 批量页面在首图、主体交互和正文节奏上有与机制相关的差异；不是同一模板更换名词。
- [ ] 需要授权或执行的动作不跳过阶段；文本流式、工具出现、返回结果和后续判断顺序正确。
- [ ] 输入变化、场景切换、回到上一步或重播不会保留无效结果，旧计时器不会污染新场景。
- [ ] 未完成、被拒绝、无进展与达到预算不显示成功。只覆盖当前场景实际存在的分支。

### 四页的具体验收例子

| 页面 | 操作 | 预期证据 |
| --- | --- | --- |
| Harness | 运行一次修服务；观察工具与文本；切到未通过或拒绝场景 | 用户消息在右；工具动作不抢在前置文本结束前出现；未通过时继续修正或说明缺口 |
| 工具调用 | 看执行前后；切换缺文件和未授权 | 读取前无日志；返回后才有实际报错；拒绝分支不经过文件执行，不制造成功结果 |
| 上下文 | 加入本次日志与要求，查看回答；移出日志；只选旧记录 | 卡片位置与输入一致；旧回答失效；缺少本次证据时不能用上周问题断定本次原因 |
| 智能体循环 | 补冒号并检查；继续改返回值；调整轮数或重复同一操作 | 代码先修改，检查后才显示 500/200；上限与无进展保持未完成状态，重置清空旧进度 |

这些是场景验收示例，不要求新词条也有同样的分支、轮数或报错。

## 动画、布局与阅读

- [ ] 初态、过渡中间态和终态可读；没有重要文字被叠层遮住、没有明显闪现或布局跳动。
- [ ] 展开与收起均有过渡，隐藏内容不可误点击或聚焦；快速操作不会留下幽灵元素。
- [ ] 自动演示可暂停、推进、重播；有限播放会结束，离开可见区域或隐藏页面后暂停。
- [ ] 减少动态效果时信息与操作完整，不留透明空图；没有持续运动影响阅读。
- [ ] 演示在所有场景和展开状态中与正文同宽；长代码、报错、链接和控制器不造成横向溢出。
- [ ] 窄屏保留正常字体与操作面积，不把桌面整图缩成不可读的小图；大屏标题无不合理孤字。
- [ ] 图标轮廓正常，星星没有替代所有语义图标；控制区没有无意义横线和重复脚注。
- [ ] 连续操作无可见闪屏或持续卡顿；状态改变只更新相关部分，不复制全局鼠标或星图动画循环。

## 基础交互：只查受影响的部分

- 目录：文字对应正文，滚动更新活动项，活动项自动保持可见，点击落点不被页头遮挡。
- 卡片：主题色虚线提示可点击；键盘可打开和关闭；窄屏卡片不出界，焦点可返回。
- 书目：hover 不展开；小三角与键盘可开合；角标到书目、摘录回正文均正确，折叠区内的目标能先展开。
- 局部星图：中心词条正确、关联来源真实；悬停/聚焦有名称，选择有连线和入口，拖动不会误跳转，普通滚动仍用于阅读文章。
- 输入：若有发送框，输入、发送、用户消息位置和预设回答工作正常；快速发送或切换不串场。
- 键盘与读屏：控件有名称、焦点清晰，状态变化不过度播报；信息不只依赖 hover 或颜色表达。

## 验证顺序与停止条件

1. 对照本次选定的范围，检查实现与事实。
2. 应用代码先执行 `npm run build`；失败时处理具体问题。`npm run check` 仅在项目验收或发布要求需要全套检查时执行。
3. 按当前项目规则对受影响交互做真实浏览器操作，同时看画面。构建通过不代表交互通过，DOM 里有文字也不代表用户看得见。
4. 确认动画终态之外的关键顺序，例如执行中尚无结果、收起时还有淡出。只抽查机制需要的中间状态，不制作无意义的逐帧测试。
5. 发现缺陷按项目规则记录和修复，回归相应项；无新改动、失败或疑点时停止追加验证。未改的已验证组件不反复全量检查。
6. 不可验证的部分标明原因和最小手动核对方式；不能写成通过。计划或用例只记录实际执行或明确要求的测试。

不把代码检查、模拟示例通过、远端集成验证、用户认可视觉、生产上线混为一个“完成”。

## 最小交付记录

把有效记录放进项目已有位置，不为每一步创建新文档。可按下列信息交付：

- 页面与范围：词条、可打开的预览 URL、实际可见的改动；
- 内容依据：新增或修正了什么事实，对应哪些已核对来源；
- 验证：构建结果、实际操作和观察结果、相关视口、未验证项；
- 研发阶段：相关 DP 编号及真实状态，分支/提交/PR，实际发生的部署与回滚信息；
- 剩余事项：仅列真实缺口或待用户设计验收的部分。

遵从当前授权和项目交付规则，不因使用本 Skill 自动取得生产发布或其他外部操作权限。
